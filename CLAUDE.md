## Project

A personal website with a blog (Serbian, Latin script), built on Next.js 16 (App Router) with React 19, TypeScript and Tailwind CSS v4. No database and no CMS: all content is MDX files in the repo, and the user writes new posts together with Claude. The user communicates in Serbian; all UI text is in Serbian (Latin).

## Commands

- `npm run dev` — dev server at http://localhost:3000 (Turbopack)
- `npm run build` — production build; also runs the TypeScript check
- `npm run start` — serve the production build
- `npm run lint` — ESLint (flat config, `eslint-config-next` core-web-vitals + typescript)

No test framework is set up. Verify changes with `npm run lint` and `npm run build` (the route table should show posts and tags as prerendered).

## Adding a blog post

1. Create `content/posts/<slug>.mdx`. The file name is the URL (`/blog/<slug>`); use lowercase ASCII with hyphens (č/ć→c, š→s, ž→z, đ→dj).
2. Start it with a YAML header:
   ```yaml
   ---
   title: "Naslov posta"
   date: "2026-10-20"          # YYYY-MM-DD, quoted
   description: "Jedna-dve rečenice za listu postova, SEO i RSS."
   tags: ["tag1", "tag2"]      # free text; URL slug is generated by tagSlug()
   cover: "/images/posts/<slug>/naslovna.jpg"   # optional
   draft: true                 # optional; hidden in production, shown in dev
   ---
   ```
3. Write the body in Markdown (GFM tables work). Don't repeat the title as `# h1`; the page renders it from the header.
4. Put images in `public/images/posts/<slug>/` and reference them as `![opis](/images/posts/<slug>/slika.jpg)`.

Nothing else needs registering: lists, tag pages, RSS and the sitemap read `content/posts/` automatically. The "O meni" page text is `content/o-meni.mdx`.

## Architecture

- `src/lib/site.ts` — site name, description, author, URL, social links. Values marked `TODO` are still placeholders; `url` must be set to the real domain once the site is deployed (used by RSS, sitemap, Open Graph).
- `src/lib/posts.ts` — reads post headers with `gray-matter` (`getAllPosts` is `"use cache"`), reading time, tags, `formatDate` (`sr-Latn-RS`).
- MDX bodies are compiled by `@next/mdx` (configured in `next.config.ts`; `remark-frontmatter` strips the header, `remark-gfm`). `src/app/blog/[slug]/page.tsx` loads the body with a dynamic `import()` of `content/posts/${slug}.mdx`. Element overrides (images → `next/image`, links) are in `src/mdx-components.tsx`.
- Routes: `/`, `/blog`, `/blog/[slug]`, `/blog/tag/[tag]`, `/o-meni`, `/rss.xml`, `/sitemap.xml`, `/robots.txt`.

## Next.js version notes

Next.js 16 differs from older versions; consult `node_modules/next/dist/docs/` (`01-app/` is the App Router guide) before using APIs you're unsure of. Notable settings in `next.config.ts`:

- `cacheComponents: true` — Cache Components mode is on. Data reads (like `fs` in `posts.ts`) and non-deterministic values (like `new Date()` in `Footer`) must be inside `"use cache"` or the build fails. `dynamicParams` is not available; unknown slugs are handled with `notFound()`.
- `partialPrefetching: true`
- Tailwind is wired in through a Turbopack loader rule for `*.css` (`@tailwindcss/turbopack`), not PostCSS. Turbopack requires remark/rehype plugins to be passed to `createMDX` as strings.

Layouts/pages use the globally generated route types, e.g. `LayoutProps<"/">`, `PageProps<"/blog/[slug]">`, rather than hand-written prop types. Types are generated into `.next/types` during dev/build.

## Structure and styling

- Source lives in `src/`; App Router routes in `src/app/`, shared components in `src/components/`. Import alias `@/*` → `src/*`. Content lives outside `src/` in `content/`.
- Styling: Tailwind v4 configured CSS-first in `src/app/globals.css` (`@import "tailwindcss"` + `@theme inline` + `@plugin "@tailwindcss/typography"`), no `tailwind.config` file. The brand palette (user-provided, source in `originali/paleta.png`) is exposed as Tailwind colors: `lime` #92FF5F, `green` #103B28, `soft-white` #F7F9F7, `orange` #FF7036, `ice` #BFF2F0, `mint` #CFF1D2. There is one brand theme (dark green background, soft white text, lime accent) and no light/dark mode; the home "Moda" section is on `bg-soft-white`. Post text uses `prose`, mapped to the palette.
- Fonts: Geist (body), Geist Mono and Inter Tight (`font-display`, headings) via `next/font/google` in `src/app/layout.tsx`, all with the `latin-ext` subset (needed for č, ć, š, đ, ž).
- Pages set their own width container (`mx-auto max-w-6xl` for lists, `max-w-2xl` for reading); the root layout's `<main>` is full width so the home hero can be edge to edge.

## Home hero animation

`src/components/HeroCamera.tsx` (client component): a tall section with a sticky viewport. On scroll, the video `public/video/kamera.mp4` (a camera being wound) zooms into the lower lens, `public/images/hero/casopisi.jpg` opens up inside the lens (circle `clip-path`) until it fills the screen, then the closing text appears. The `LENS` constant holds the lens position/size as fractions of the video frame; update it if the video is replaced. The video is a compressed copy (1080p, no audio) of `originali/video.mp4`; `originali/` holds large source files and is gitignored. `prefers-reduced-motion` shows the final state without animation.

## Newsletter

The home page form (`src/components/Newsletter.tsx`) calls the Server Action `subscribe` in `src/app/actions/newsletter.ts`, which adds the address to Resend contacts (`resend` SDK) and, if `RESEND_FROM_EMAIL` is set, sends a welcome email. Env variables are documented in `.env.example` (copy to `.env.local`): `RESEND_API_KEY` (required), `RESEND_SEGMENT_ID` (optional), `RESEND_FROM_EMAIL` (set only after the sending domain is verified in Resend). Newsletters themselves are sent from the Resend dashboard (Broadcasts).
